### Constructors / Destructors

"default constructor" is a constructor that **can be** called with no arguments. This means, "default constructor" may have no input arguments, or may have input arguments with default values. A class doesn't necessarily have to have default constructor.
Use initialization list with constructor for member variables. It is more efficient as using assignment operator in the body of constructor (`m_name = "Alice"`). This way we save unnecessary construction of temporary objects of type member variables. 

#### Difference between copy constructor and assignment operator

Copy constructor uses the contents of an existing object to create/initialize a new object. Whereas in assignment operator (=), we set the contents of an existing object to another existing object.
Like a normal function member, assignment operator should return something. The input argument can not be copy of the object. Must be reference.

Copy constructor vs assignment operator:
```c++
#include <string>
#include <iostream>


class Student
{
public:
    // Constructor (and in this case, conversion constructor, because it accepts one argument)
    Student(std::string name)
    {
        m_name = name;
    }

    // Copy constructor
    Student(const Student& s)
    {
        m_name = s.m_name;
    }

    // Assignment operator
    // Assignment operator should return something. The input argument can not be copy of the object. Must be reference.
    Student& operator=(const Student& s)
    {
        m_name = s.m_name;
        return *this; // this is a pointer to the object. ==> *this is the object!
    }

    std::string m_name;

};

int main(int argc, char* argv[])
{
    Student alice("Alice");
    Student ben = alice; // Using copy constructor

    std::cout << "alice.m_name = " << alice.m_name << std::endl; // Prints alice.m_name = Alice
    std::cout << "ben.m_name = " << ben.m_name << std::endl; // Prints ben.m_name = Alice

    Student jerry("Jerry");
    jerry = alice; // Using assignment operator
    std::cout << "jerry.m_name = " << jerry.m_name << std::endl; // Prints jerry.m_name = Alice

    return 0;
}
```

#### Conversion constructor vs conversion operator
Conversion constructor is a constructor with only one input argument. Having conversion constructor, we can initiate the object in two different ways. 

Conversion operator:
- has no return.
- has no input argument.
- better to be called with keyword `explicit` to prevent unwanted type conversion. But then casting is necessary too.

Conversion constructor vs conversion operator:
```c++
#include <string>
#include <iostream>

class Student
{
public:
    // conversion constructor (accepts only one input argument)
    Student(std::string name)
    {
        m_name = name;
    }

    // Conversion operator
    explicit operator std::string()
    {
        return m_name;
    }

    std::string m_name;
};

int main(int argc, char* argv[])
{
    Student eva = std::string("Eva"); // Using conversion constructor (type conversion by constructor)
    std::cout << "eva.m_name = " << eva.m_name << std::endl;

    // Using conversion operator
    //std::string name = eva; // Error because of keyword explicit
    std::string name = static_cast<std::string>(eva); // Casting needed because of keyword explicit
    std::cout << "name = " << name << std::endl; // Prints name = Eva

    return 0;
}
```
#### Named constructor
Imagine you have a class for defining a point. This point can be defined in rectangular coordinates(`x` and `y`) or in polar coordinates (radius and angle). Two constructors for class `Point`, both accepting two doubles as input arguments --> compiler error.

The solution is "named constructors":
1. Define two `public` static function members for `Point`, one for rectangular and one for polar. These are "named constructor"s.
2. Define one constructor with two double input arguments under `private` specifier.

So "named constructor" actually is not a real constructor. It is a static function member.
```c++
#include <cmath>
#include <iostream>
#include <string>

class Point
{
public:
  // Named constructors (which actually are not really constructors!!!) 
  static Point rectangular(double x , double y);
  static Point polar(double radius , double angle);

  std::string getXString() const {return std::to_string(m_x);};
  std::string getYString() const {return std::to_string(m_y);};

private:
  Point(double x, double y);
  double m_x = 0;
  double m_y = 0;
};

// "inline" when the definition of a function member is outside the class body but inside header file
inline Point::Point(double x, double y) : 
m_x(x),
m_y(y)
{ }

inline Point Point::rectangular(double x, double y)
{
    return Point(x,y);
}

inline Point Point::polar(double radius, double angle)
{
    return Point(radius*std::cos(angle*3.14/180), radius*std::sin(angle*3.14/180));
}

int main(int argc, char* argv[])
{
    Point p1 = Point::rectangular(0.7 , 0.7); // Using named constructor
    Point p2 = Point::polar(1 , 45); // Using named constructor

    std::cout<< "(p1.x,p1.y) = (" << p1.getXString() << "," << p1.getYString() << ")" << std::endl; // Prints (p1.x,p1.y) = (0.700000,0.700000)
    std::cout<< "(p2.x,p2.y) = (" << p2.getXString() << "," << p2.getYString() << ")" << std::endl; // Prints (p2.x,p2.y) = (0.707388,0.706825)

    return 0;
}
```
**Tip:** Notice that we use the keyword `inline` when the definition of a function member is outside the class body but inside header file.

#### Destructor
- Takes no input argument.
- Returns no value. (`~ClassName(){}`)
- We almost never call it in code. It will be called when the object goes out of scope `{...}`. Or by dinamic memory allocation, when we call `delete()`. Notice that `delete()` does two things:
  1. Calls destructor.
  2. Deallocates memory.
- We can not have virtual constructor, but we can have virtual destructor. Depending on the object type, the proper reimplementation of destructor will be chosen and called at runtime.


### Inheritence
#### Public inheritence vs private inheritence
We have class `A`. If we derive `class B : public A`, all public members of `A` will be public in the object of class `B` as well.  

We have class `A`. If we derive `class B : private A`, all public members of `A` will be only available within class `B` body and not outside of it. In other words, all public members of `A` will be private members in `B`.

```c++
#include <iostream>
#include <string>

class Animal
{
    public:
    void speak(std::string whatever)
    {
        std::cout<< whatever << std::endl;
    }
};

class Dog : public Animal
{
    public:
    void bark()
    {
        speak("Bark! Bark!");
    }
};

class Cat : private Animal
{
    public:
    void meow()
    {
        speak("Meow! Meow!");
    }
};

int main(int argc, char* argv[])
{
    Dog dog;
    dog.bark(); // Prints: Bark! Bark!
    dog.speak("Hoooooo!"); // Compiles because class Dog : public Animal. Prints: Hoooooo!
    
    Cat cat;
    cat.meow(); // Prints: Meow! Meow!
    // cat.speak("Meeeeeeeow!"); // Doesn't compile because class Cat : private Animal

    return 0;
}

```
Do we really need private inheritence? I am not sure. The goal in private inheritence is that for example class `Cat` wants to include the attributes and possibilities of class `Animal` inside itself. In fact, in above example, the base-derived relationship between `Animal` and `Cat` is not defined properly because of private inheritence. Public inheritence says: *Dog **is** an Animal*. Private ihneritence says: *Cat **includes** an Animal*, which is not really correct. In modern C++, we use the concept of "composition" instead: Instead of private inheritence from the class, we use a private member variable of the class. For example below we have the class `Engine`. The class `Car` is not sort of `Engine`. `Car` includes an `Engine`. This can be done by private inheritence, or by "composition":
```c++
#include <iostream>
#include <string>

class Engine
{
    public:
    void start()
    {
        std::cout<< "Ju Ju Ju Ju .....";
    }
};

class Car : private Engine
{
    public:
    void run()
    {
        start();
        std::cout << "And here we goooo..." << std::endl;
    }
};

class ModernCar
{
    private:
    Engine m_engine; // Concept of "composition" instead of private inheritence
    public:
    void run()
    {
        m_engine.start(); // Concept of "composition" instead of private inheritence
        std::cout << "And here we goooo..." << std::endl;
    }
};

int main(int argc, char* argv[])
{
    Car car;
    car.run(); // Prints: Ju Ju Ju Ju .....And here we goooo...
    //car.start(); // Doesn't compile because class Car : private Engine

    ModernCar modernCar;
    modernCar.run(); // Prints: Ju Ju Ju Ju .....And here we goooo...

    return 0;
}

```
Now! Two differences between C++ class and struct:
1. Default members in struct are public. In class are private.
2. Default inheritence in struct is public. In class is private. This means, in above code `class Car : Engine` = `class Car : private Engine`.

#### Virtual vs override
We have a function in base class. We override the function in derived class. The same signature, but two implementations in base and derived class.

If we declare the function in base class as `virtual`, we enable "runtime polymorphism". We let the compiler to check the actual object type and to call the proper implementation at runtime.
```c++
#include <iostream>
#include <string>

class Animal
{
    public:
    void sound()
    {
        std::cout << "Some sound" << std::endl;
    }

    virtual void sound2()
    {
        std::cout << "Some sound 2" << std::endl;
    }
};

class Dog : public Animal
{
    public:
    void sound() // overriding Animal::sound()
    {
        std::cout << "Bark! Bark!" << std::endl;
    }

    void sound2() override // 
    {
        std::cout << "Bark2! Bark2!" << std::endl;
    }

};

int main(int argc, char* argv[])
{
    Animal* a = new Dog();
    a->sound(); // Override. Prints: Some sound
    a->sound2(); // Runtime polymoorphism. The compiler decides at runtime. Prints: Bark2! Bark2!

    return 0;
}
```
